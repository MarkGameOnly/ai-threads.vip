# AI Threads 5.6.5 — авторежим с переходом в ветку

## Причина возвратов

maybeRotate выполнялся перед обработкой сохранённой попытки. Страница ветки
не совпадала с источником «поиск», и движок уходил в поиск прежде отправки.
Дополнительно обычный переход по счётчику «Ответ2» расценивался как промах,
а «Ещё Ещё» (aria-label плюс innerText) проходило фильтр с точным ^ещё$.

## Изменения

Авторежим выбирает пост и генерирует текст, сохраняет их в _engine.activeReply,
открывает пермалинк, завершает цикл старой страницы и после загрузки продолжает
сохранённый ответ. Ротация источника не прерывает незавершённый ответ.
Карточка, не найденная парсером, не заставляет терять цель: сохранены её данные.
После отправки или окончательного отказа состояние очищается, затем движок
возвращается к источнику. Команда в чате агента для этого не нужна.

На странице ветки приглашение «Ответьте …» проверяется перед строкой действий,
в том числе если приглашение является соседним элементом карточки.
Счётчики Ответ2/Ответ36 не открываются как редактор; «Ещё» отсекается и при
дублированной подписи. Переход на целевую ветку в DOM-операции не вызывает
history.back; чужие переходы по-прежнему блокируются.

Подтверждение отправки учитывает перемонтированный редактор с оставшимся текстом,
переспрашивает карточку для счётчика и не засчитывает навигацию как успех.
Пустое поле без подтверждения остаётся RISKY_CONSUMED: это неопределённый результат,
а не доказательство ошибки отправки. Повторная отправка запрещена для защиты от дубля.

# AI Threads 5.6.4 — исправления по логам от 08.10.2026

## Что найдено

В commentOnPost при отсутствии карточки контейнером становился document.body.
replyTargets и резервный поиск сканировали всю страницу: можно было выбрать
«Ответ15» у другого поста. replyPromptTargets тоже искал по всей странице;
регулярное выражение с ответ\b ошибочно допускало «Ответ15», поскольку JavaScript
не считает кириллицу символами слова. Проверка navigatesAway смотрела href
только у выбранного узла и не замечала ссылку его родителя.

Отсутствие постов сразу после загрузки приводило к немедленной ротации источника
после одного пустого прохода. Отложенный resume мог повторно войти в уже запущенный
движок. Сообщение «Начни с Калибровки» печаталось при каждой полной загрузке
страницы и само по себе не означало ошибки.

## Исправления

- Кнопки ответа ищутся внутри целевой карточки; глобальный поиск строк действий удалён.
- При отсутствии карточки в ленте/поиске возвращается CONTAINER_MISSING;
  движок может выполнить предусмотренную повторную попытку через пермалинк.
- Без карточки на целевом пермалинке остаётся поиск явной формы ответа;
  лайк по всей странице больше не выполняется.
- Приглашения к вводу ищутся в указанной области; счётчики Ответ9/15/10 и Reply15 исключены.
- Проверка ссылок учитывает ближайший родительский a[href], домен и query string.
- Пустой странице дано 15 секунд перед принудительной ротацией источника.
- resume не перезапускает существующий цикл; сообщение готовности уточнено.
- Код синхронизирован для desktop, Android и mobile; версия 5.6.4.

## Установка

Desktop: распаковать builds/extension-desktop.zip. В chrome://extensions
включить режим разработчика и загрузить папку extension как распакованное расширение.
Если существующее расширение установлено из исходной папки, замените её содержимое,
нажмите «Обновить» у расширения, затем перезагрузите вкладку Threads.
Сначала остановите комментинг и проверьте ответ на одном выбранном посте.

Для Android и mobile подготовлены отдельные ZIP с соответствующими манифестами.
Установка из распакованной папки зависит от возможностей браузера.
